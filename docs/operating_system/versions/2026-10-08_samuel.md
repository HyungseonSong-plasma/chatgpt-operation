# Samuel Operating-System Baseline — 2026-10-08

**State:** ACTIVE at creation  
**Generation:** Controller-Native / Skill-Optimized  
**Predecessor:** Paul — Rule-Minimal / Skill-Optimized

## Purpose

Samuel is the material successor to Paul. It preserves Paul's minimal essential-rule layer and deterministic skill delegation, then makes the durable controller, capability routing, exact-head validation, verified native mutation, and deterministic recovery paths part of the operating-system architecture itself.

Samuel does not move consumer scientific/domain semantics into the central controller.

## Canonical architecture

```text
exact immutable central revision
  -> Samuel essential rules
  -> trigger-resolved skills
  -> capability registry
  -> durable Samuel controller lifecycle
  -> verified execution / postcondition readback / recovery
  -> consumer-local semantic and scientific authority
```

## Essential invariants

Samuel preserves the authority and evidence boundaries introduced by Paul:

- durable repository/system evidence outranks conversational memory;
- one exact immutable central revision is used per operating decision cycle;
- initialization is read-only and fail-closed;
- central mechanics do not redefine consumer semantics;
- current mutable state is refreshed before mutation/current-state claims;
- evidence classes are not promoted by implication;
- unresolved material gates stop the affected path;
- interrupted work resumes from durable checkpoints;
- documentation records accepted state rather than creating truth.

Samuel adds one architectural invariant:

- capability-backed mutation must resolve an explicit owner, verify exact decision-critical preconditions, and verify the desired postcondition after execution.

## Capability routing

`skills/capability-registry.json` is authoritative for registered multi-provider capabilities.

For `GITHUB_PR_MERGE`, the registered provider order is:

```text
1. github-connector
2. repository-native
   -> samuel-controller.yml
   -> samuel-native-github.yml
```

Capability exhaustion is not established until all registered providers allowed by the current contract have been evaluated.

## Pull-request merge safety

Samuel's native merge contract requires:

```text
PR exact head SHA == expected head SHA
mergeable == true
CI == success
desired postcondition == merged true
```

Execution is:

```text
read-before
  -> verify mandatory preconditions
  -> mutate with expected head SHA
  -> read-after
  -> verify merged postcondition
```

A stale/moved PR head fails closed. A rejected exact-head merge is not silently retried on the same stale branch; it enters deterministic recovery.

## Initialization

`skills/session-bootstrap/README.md` remains the portable initialization owner.

A successful Samuel consumer initialization must verify:

```text
exact central revision
Current version name = Samuel
Samuel ESSENTIAL_RULES
required init skills from the same revision
consumer repository identity
durable consumer work state
immediate obligation / first real gate
```

Initialization itself does not grant mutation authority.

## Ownership boundary

Central Samuel owns generic mechanics:

```text
OS lifecycle
essential cross-repository invariants
skills/capability routing
durable generic controller mechanics
repository/GitHub mutation contracts
checkpoint/resume and recovery mechanics
```

The consumer remains authoritative for:

```text
domain/scientific semantics
compatibility commitments
repository-specific policy
acceptance criteria
local roles/modes
runtime/scientific evidence meaning
```
